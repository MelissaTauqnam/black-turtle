      Étape 1 · L'idée générale
      
Une application, c'est un restaurant

      
Avant de parler technique, une image. Une application web a une partie que l'on voit (la salle) et une partie qui travaille en coulisses (la cuisine). Dans ce guide, Claude Code aide à construire la salle et n8n tient la cuisine.

    


    

      

        
🪑

        La salle
        
Le client passe commande

        
Il voit un menu, choisit, remplit sa commande. Il ne voit jamais la cuisine.

        
En vrai : l'interface, par exemple un formulaire sur une page web. C'est ce que Claude Code vous aide à coder.

      

      

        
🧾

        Le bon de commande
        
La commande part en cuisine

        
Le serveur transmet un bon, toujours au même format, par le même passe-plat.

        
En vrai : une requête envoyée au webhook, avec les données au format JSON.

      

      

        
👩‍🍳

        La cuisine
        
La recette est exécutée

        
Les cuisiniers suivent une recette, étape par étape, et font appel aux fournisseurs si besoin.

        
En vrai : le workflow n8n. Chaque étape est un nœud ; les fournisseurs sont Gmail, Slack, une IA…

      

      

        
🍽️

        Le plat servi
        
Le client reçoit le résultat

        
Le plat revient en salle, et le client voit que sa commande est prête.

        
En vrai : la réponse de n8n, que l'interface affiche (« Merci, on vous rappelle ! »).

      

    


    

      

        Le « front » (front-end)
        
Ce que l'utilisateur voit

        
Pages, boutons, formulaires, affichés dans le navigateur. On l'écrit en HTML (la structure), CSS (l'apparence) et JavaScript (les interactions). C'est ce que vous construisez avec Claude Code.

      

      

        Le « back » (back-end)
        
Ce qui travaille en coulisses

        
Recevoir les données, les vérifier, appeler d'autres services, enregistrer, prévenir. D'habitude, cela demande beaucoup de code. Ici, c'est n8n qui joue ce rôle, sous forme visuelle.

      

    


    

      
?

      

        
Pourquoi séparer les deux ?

        
Parce que chaque outil fait ce qu'il fait le mieux. Claude Code produit rapidement une interface propre et sur mesure. n8n rend la logique métier visible : on voit chaque étape, on la modifie sans toucher au site, et on garde l'historique de ce qui s'est passé.

        
Autre avantage : les mots de passe et accès à vos outils (Gmail, CRM…) restent rangés dans n8n. Ils n'apparaissent jamais dans la page web, que n'importe qui peut inspecter.

      

    

  







  

    

      Étape 2 · Les bases de n8n
      
n8n en six notions

      
n8n est un outil d'automatisation : on y dessine un workflow en reliant des blocs, et n8n l'exécute tout seul. Pas besoin de savoir coder pour commencer ; on peut ajouter du code plus tard si nécessaire.

    


    

      

        

        
1. Le déclencheur

        
C'est le premier bloc, celui qui démarre le workflow. Il répond à la question « quand ? » : tous les lundis à 9 h, à chaque nouvel email, quand quelqu'un envoie un formulaire…

        
En clair : c'est le « top départ ». Sans déclencheur, rien ne se passe.

      

      

        

        
2. Les nœuds

        
Chaque bloc (appelé nœud) fait une seule chose : envoyer un message Slack, lire un tableur, poser une question à une IA, trier des données…

        
En clair : ce sont les étapes de la recette, reliées par des flèches.

      

      

        

        
3. Les données (items)

        
Le long des flèches circulent des données au format JSON. Chaque « paquet » de données est un item. Si 10 personnes remplissent le formulaire, 10 items passent.

        
En clair : chaque nœud reçoit des données, les traite, et passe le résultat au suivant.

      

      

        

        
4. Les expressions

        
Dans un champ, on peut écrire {{ $json.email }} au lieu d'un texte fixe. n8n remplace alors la formule par l'email de la personne en cours.

        
En clair : c'est comme un publipostage : « Bonjour {{ prénom }} ».

      

      

        

        
5. Les agents IA

        
Le nœud AI Agent confie une tâche à une IA (un modèle de langage comme Claude). On peut lui donner des outils : chercher dans le CRM, envoyer un email…

        
En clair : un assistant qui lit, résume, classe ou rédige à votre place, au milieu du workflow.

      

      

        

        
6. Les exécutions

        
Chaque fois que le workflow tourne, n8n enregistre une exécution : ce qui est entré et sorti de chaque nœud, et où ça a bloqué en cas d'erreur.

        
En clair : le journal de bord, indispensable pour comprendre un problème.

      

    


    

      

        Lire une donnée JSON
        
Le JSON, c'est juste une fiche avec des étiquettes

        
Vous en verrez partout : dans n8n, dans les réponses d'API, dans le code généré par Claude Code. Pas besoin de l'écrire à la main, mais il faut savoir le lire. Quatre règles suffisent.

      

      


{1
  "entreprise": "Boulangerie Martin",2
  "salaries": 24,3
  "client": false,
  "besoins": ["commandes", "factures"]4
}

    2. 
          
  2. "étiquette": valeur, séparées par des virgules. Le texte est toujours entre guillemets.
    3. 
          
  3. Les nombres et true / false (vrai / faux) s'écrivent sans guillemets.
    4. 
          
  4. Les crochets [ ] contiennent une liste de valeurs.

        Le point clé pour relier une interface
        
Le nœud Webhook : la sonnette de votre workflow

        
Quand vous ajoutez un déclencheur Webhook, n8n vous donne une adresse web (une URL). Chaque fois qu'un programme envoie des données à cette adresse, le workflow démarre avec ces données.

        
    
          
  • Une adresse pour tester, une pour de vrai. L'URL de test sert pendant la construction ; l'URL de production marche en permanence une fois le workflow activé.
    • 
          
  • Vous décidez de ce qui est renvoyé. Le nœud Respond to Webhook (« répondre au webhook ») renvoie à l'interface exactement le message que vous voulez.
    • 
          
  • La sonnette peut être protégée. On peut exiger une clé secrète pour que seuls vos programmes puissent déclencher le workflow.
    • 
        

      

      

        
Exemple : réglages d'un nœud « Slack »formule → résultat

        

          Canal où poster
          #ventes-{{ $json.region }}
          → #ventes-idf
        

        

          Message
          Nouveau prospect : {{ $json.entreprise }}, score {{ $json.score }}/100
          → Nouveau prospect : Boulangerie Martin, score 86/100
        

        

          Comment lire la formule
          {{ }} = « calcule ceci » · $json = « les données du bloc précédent » · .region = « l'étiquette region »

Et le retour ?

        
À la fin, n8n renvoie une réponse à l'interface par le même chemin, en sens inverse. Elle contient un code de statut (200 = tout va bien) et un petit message JSON. L'interface lit ce message et affiche « Merci ! » ou une erreur compréhensible.

      Bonnes pratiques
      
Six réflexes pour passer de la démo à un vrai outil

      
Les trois premiers sont indispensables dès qu'un vrai public utilise votre interface.

    

    

      
Indispensable
Protéger la sonnette
Activez l'authentification sur le nœud Webhook (une clé secrète dans un en-tête). Pourquoi ? Sans elle, toute personne qui trouve l'URL peut lancer votre workflow.

      
Indispensable
Ne jamais mettre la clé dans la page
Le code d'une page web est lisible par n'importe quel visiteur. On passe donc par un petit intermédiaire côté serveur qui ajoute la clé. Pourquoi ? Une clé visible, c'est une clé volée.

      
Indispensable
Vérifier les données deux fois
Dans l'interface, pour aider l'utilisateur (« email invalide »). Et dans n8n, avec un nœud If. Pourquoi ? Quelqu'un peut contourner la page et envoyer n'importe quoi au webhook.

      
Recommandé
Toujours répondre pareil
Choisissez un seul format de réponse, par exemple { ok, data, error }, pour tous les cas. Pourquoi ? L'interface n'a qu'une façon de lire la réponse : moins de bugs.

      
Recommandé
Ne pas faire attendre
Si le workflow prend plus de quelques secondes, répondez tout de suite « bien reçu » et traitez en arrière-plan (asynchrone). Pourquoi ? Au-delà de 10 s, l'utilisateur pense que c'est cassé.

      
Recommandé
Être prévenu des pannes
Créez un workflow qui commence par le déclencheur Error Trigger et vous envoie un message. Pourquoi ? Vous apprenez le problème avant vos utilisateurs.

      FAQ
      
Les questions qu'on se pose au début

    

    

      

        Faut-il savoir coder pour suivre ce guide ?
        
Non pour n8n : on construit les workflows en reliant des blocs à la souris. Pour l'interface, Claude Code écrit le code à votre place ; il suffit de savoir décrire précisément ce que vous voulez et de tester le résultat. Comprendre les mots du glossaire (webhook, JSON, requête…) vous rendra beaucoup plus efficace.

      

      

        Quelle différence entre n8n, Zapier et Make ?
        
Les trois servent à automatiser des tâches en reliant des applications. n8n se distingue par la possibilité de l'installer sur son propre serveur, d'ajouter du code quand on veut, et par ses nœuds d'IA avancés. Les notions de ce guide (déclencheur, webhook, données JSON) sont les mêmes partout.

      

      

        Pourquoi mettre la logique dans n8n plutôt que dans le code du site ?
        
Parce que la logique change souvent (« prévenir aussi le service compta », « changer le seuil du score »). Dans n8n, on la modifie en quelques clics sans republier le site, et chaque exécution est enregistrée. Le site reste simple : il envoie et il affiche.

      

      

        Claude Code peut-il vraiment créer le workflow n8n lui-même ?
        
Oui, si vous le connectez au serveur MCP de votre instance n8n. Claude Code peut alors chercher les bons nœuds, construire et vérifier le workflow, le lancer en test et lire le résultat. Vous gardez la main : relisez toujours le workflow dans l'éditeur n8n avant de l'activer.

      

      

        Mon webhook ne répond pas, que vérifier ?
        
Trois causes fréquentes : 1) vous utilisez l'URL de test /webhook-test/ sans avoir cliqué sur « Listen for test event » dans n8n ; 2) vous utilisez l'URL de production /webhook/ alors que le workflow n'est pas activé ; 3) la clé envoyée ne correspond pas à celle configurée (réponse 401). Regardez aussi l'onglet « Executions » de n8n.

      

      

        n8n est-il gratuit ?
        
n8n peut être installé gratuitement sur votre propre serveur (version communautaire). Il existe aussi une version hébergée par n8n (cloud), payante, qui évite toute installation. Pour ce guide, les deux fonctionnent de la même façon ; seule l'adresse de vos webhooks change.
